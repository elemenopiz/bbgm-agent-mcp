# Safety-grant evidence bundle

This index defines what can be handed to a reviewer from the current research
preview. Generated run data live under `.data/` and are ignored by Git. A
shareable bundle must include the source revision, manifests, report, raw
episode data, and command/provenance record together.

The active claim is safety measurement: whether narrow fine-tuning on a visible
proxy creates proxy-intent divergence or oversight-sensitive behavior. The
artifacts below currently establish environment readiness, deterministic
controls, and auditability; they do not yet contain a Tinker-trained result or
the safety-specific proxy/intent experiment. See
`docs/SAFETY_GRANT_STRATEGY.md` for the required next evidence.

## Exact reproduction commands

Run from the repository root. Obtain and license the engine checkout separately;
the wrapper does not bundle it.

```sh
corepack pnpm install --frozen-lockfile
export BBGM_SOURCE_DIR=/absolute/path/to/the/pinned/zengm-checkout
(cd "$BBGM_SOURCE_DIR" && pnpm install)

corepack pnpm check
BBGM_SOURCE_DIR="$BBGM_SOURCE_DIR" BBGM_ENGINE_TIMEOUT_MS=180000 \
BBGM_EVAL_PARALLELISM=1 corepack pnpm exec tsx scripts/run-grant-demo.mts \
  --data-root .data/grant-demo-reproduction \
  --out .data/grant-demo-reproduction/long-horizon-asset-preservation-v1.json \
  --summary-out .data/grant-demo-reproduction/reviewer-summary.md

BBGM_SOURCE_DIR="$BBGM_SOURCE_DIR" node --experimental-strip-types \
  scripts/verify-grant-artifact.mts \
  --report .data/grant-demo-reproduction/long-horizon-asset-preservation-v1.json \
  --data-root .data/grant-demo-reproduction

BBGM_SOURCE_DIR="$BBGM_SOURCE_DIR" corepack pnpm research:replay \
  --report .data/grant-demo-reproduction/long-horizon-asset-preservation-v1.json \
  --data-root .data/grant-demo-reproduction \
  --out .data/grant-demo-reproduction/replay-manifest.json

BBGM_SOURCE_DIR="$BBGM_SOURCE_DIR" BBGM_ENGINE_TIMEOUT_MS=180000 \
BBGM_EVAL_PARALLELISM=1 corepack pnpm exec tsx src/research/evaluate.ts \
  --scenario scenarios/long-horizon-asset-preservation-heldout.json \
  --policy all \
  --data-root .data/grant-heldout-reproduction \
  --out .data/grant-heldout-reproduction/heldout-report.json

BBGM_SOURCE_DIR="$BBGM_SOURCE_DIR" corepack pnpm research:verify \
  --report .data/grant-heldout-reproduction/heldout-report.json \
  --data-root .data/grant-heldout-reproduction

corepack pnpm research:attest \
  --artifact-root .data/grant-ready-final-v9 \
  --artifact-root .data/grant-ready-heldout-v1 \
  --artifact-root .data/open-model-smoke-v4 \
  --artifact-root .data/meaningful-demo-v2
```

`node scripts/run-grant-demo.mts` is the canonical baseline runner. The
package script `pnpm research:demo` runs the separate meaningful capability
demo and must not be substituted for the baseline.

For the open-model boundary, follow
`experiments/open-model/README.md`. It pins the model revision, starts
`scripts/serve-local-open-model.py`, and runs
`pnpm research:open-model` against `scenarios/open-model-smoke-v1.json`. The
resulting trace records the raw response, parsed action, observation, prompt
identity, endpoint, and outcome. This is inference-only; it does not provide
Tinker rollout or training evidence.

## Current validation caveats

- `BBGM_SOURCE_DIR=.cache/zengm node scripts/verify-engine.ts` passes against
  the pinned engine identity and license hash.
- The current v9 report passes `scripts/verify-grant-artifact.mts`, and its
  replay manifest is the current shareable replay candidate. Its pilot sample
  remains small and descriptive; heuristic stalls and all no-op stalls are
  part of the result, not missing data.
- The replay manifest records working-tree state at replay time; a source
  attestation and exact checkout/diff must travel with the final bundle.
- No Tinker-trained checkpoint, rollout token/log-probability record, or
  trained-policy report exists in this checkout.

## Review order

1. Read `docs/GRANT_BRIEF.md` for the one-question framing and evidence
   boundary.
2. Verify the external engine, then run the fresh baseline commands above.
3. Inspect the canonical report's `completionStatus`, `metricComponents`,
   `trajectorySummary`, and per-episode `trajectory.jsonl`/`attempts.jsonl`.
4. Inspect `decision-timeline.json` for the concrete capability sequence.
5. Inspect the open-model report's adapter provenance and `traces/` directory.
6. Check the source attestation, replay manifest, lock identity, working-tree
   status, and exact command transcript.

Do not claim open-model competence, asset preservation, superiority to the
heuristic, statistical validation, or Tinker improvement unless a corresponding
long-horizon report and provenance artifact exists and passes the gate in
`docs/GRANT_EVIDENCE_CHECKLIST.md`.
